# GPU backend

## Route

The GPU backend uses the CUDA driver API through `bun:ffi` and kernels written as PTX, generated by `packages/gpu/src/cuda/ptx.ts` and compiled by the driver when a device is created. `nvcuda.dll` ships with the NVIDIA display driver, so no toolkit and no native build step are needed, and the project stays free of dependencies. cuBLAS belongs to the CUDA Toolkit and is not used. WebGPU is not used because Bun has no built-in implementation.

## Status

Implemented and covered by tests: device discovery, initialisation, memory allocation and accounting, upload and download, fill, add, scale, and batched matrix multiplication for all four transpose modes with alpha and beta. A self-test checks the device numerically before `auto` or `gpu` will use it.

Not implemented: GPU training, mixed precision, GPU inference. `train --device gpu` refuses to run; `--device auto` reports what it found and trains on the CPU.

## Rules

- A buffer belongs to one device. Operations between devices throw.
- `DeviceTensor` is a different type from `Tensor`, so CPU-only code cannot receive it.
- `auto` falls back to the CPU only when the GPU fails to initialise or fails the self-test, and says why. `gpu` never falls back.
- Float32 only. Only Windows with a recent NVIDIA driver has been targeted; other platforms are untested.

## Commands

- `bun run gpu` lists devices, runs the self-test and shows the selection.
- `bun run benchmark:gpu` compares GPU and CPU SIMD matrix multiplication and writes a JSON report to `data/benchmarks`.
